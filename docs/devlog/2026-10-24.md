## 다국어 틀, 아이템·몬스터 이름 (dc#58)

### 사용자 요청
- 용어집 PR을 머지하고 다음 단계 진행 (2단계 번역 틀 + 3단계 아이템·몬스터)

### 바꾼 것
- **`i18n.js`** (번역 틀): 언어별 문구 표(`i18n/en.js` · `i18n/ja.js`)를 모으고, 번역이 없으면 한국어 원문을 그대로 보여 줌
  - 언어는 상점과 같은 `rl_lang`. 단 **게임 화면 번역이 끝나기 전(`READY = false`)에는 게임이 항상 한국어** — 상점에서 영어를 고른 사람의 게임이 반쯤 영어가 되지 않게
  - 미리 보기: 주소에 `?lang=en` / `?lang=ja` → 그 탭에서만 그 언어, 위쪽에 언어 고르기가 보임. `?lang=ko`나 고르기에서 한국어로 끝
  - 페이지를 열 때 아이템·몬스터 데이터의 이름을 그 언어로 바꿔 둠 (언어를 바꾸면 다시 읽음)
- **아이템 이름**: 등급·부위·종류·능력치·세트(조각 이름까지)·보석·유니크(효과 설명까지)·속성·강화석, 룬워드 특수 효과 13줄
  - 영어는 영어식 순서: `+3 Legendary Hell Bracers of Frost`, `+10 Ancient Yeomra's Robe`. 일본어: `古代 +10 地獄の氷 レジェンダリー 兜`
  - 룬은 어느 언어든 한글: `가 Rune` / `ルーン「가」`. 룬워드는 이름이 룬 조합의 열쇠(초성)라 원래 이름은 두고 보여 줄 이름만 따로
- **몬스터 이름**: 일반 40종·보스 3·황금 고블린 3단계·네임드 5(칭호까지), 정예·악몽의·지옥의·속성 수식어
  - 영어 `Blazing Nightmare Elite Rat`, `Gumiho — The Nine-Tailed Fox`. 일본어 `悪夢の炎のエリートネズミ`, `九尾の狐 — 千年を生きた妖狐`
  - 몬스터 이름 짓기를 문자열 바꾸기(`악몽의 ` → `지옥의 `)에서 원래 이름 + 던전·속성으로 바꿈 (한국어 결과는 그대로)
- 게임·최고 조합·랭킹 페이지가 번역 틀을 불러옴. 화면의 메뉴·안내·전투 기록은 아직 한국어 (4~5단계)

### 테스트
- 한국어 이름이 바뀌기 전과 똑같은지: 몬스터(정예·나이트메어·헬·보스·네임드·황금 고블린), 아이템 이름·보석·룬·홈·룬워드 효과
- 영어·일본어: 아이템 이름 50개·유니크 15·룬워드·보석·룬·몬스터 → 룬 말고 한글 0개
- 브라우저 11개: 기본 한국어(고르기 숨김) → `?lang=en` 영어 이름 → 주소 없이도 그 탭은 유지 → 고르기로 일본어 → 한국어로 끝, 상점 `rl_lang`은 그대로, 최고 조합·랭킹도 열림
- JS·PHP 아이템 일치 그대로
- 번역 틀을 불러도 한국어 문구 1,661줄(아이템 이름·능력치·보석·룬·룬워드 효과·몬스터)이 틀 없이와 똑같음
- 전체 회귀 테스트: 처음엔 8개 테스트에서 실패 — 번역 틀이 "번역 없음"을 `null`로 돌려줘서 한국어 원문 대신 `null`이 나옴(보석·룬 이름 등) → 고친 뒤 모두 통과 (기존 ranking-e2e 7개만 그대로)

## 게임 언어를 IP 나라로 자동 설정 (dc#61)

### 사용자 요청
- "상점에서 고른 언어보다는 게임에서도 아이피에 따라 언어가 우선 자동 설정되고 원하면 언어를 바꿀 수 있게"

### 바꾼 것
- 게임 언어 순서: **게임에서 직접 고른 언어**(`rl_game_lang`) → **접속한 IP의 나라**(한국 한국어 · 일본 일본어 · 나머지 영어) → 브라우저 언어 (ko·ja 말고는 영어). 상점에서 고른 언어(`rl_lang`)는 이제 게임 언어를 바꾸지 않음
- 서버 `GET api.php?r=geo`: 나라 코드만 돌려줌 (IP는 저장·기록하지 않음). Cloudflare `CF-IPCountry` → 웹 서버 GeoIP 모듈 → PHP geoip 확장 → MaxMind DB(`geo_mmdb`) 순, 없으면 `null`
- 게임은 나라를 하루에 한 번만 물어 `rl_geo`에 보관. 처음 방문에 나라로 정한 언어가 지금과 다르면 한 번만 다시 읽음
- 언어 고르기에 **🌐 자동** 추가: 고른 언어를 지우고 IP 나라로 돌아감
- 지금은 번역이 끝나기 전(READY = false)이라 실제 게임은 계속 한국어이고 나라도 묻지 않음 (6단계를 마치면 켜짐)

### 테스트 (20개)
- 서버: 나라 모름 → `null`(캐시 안 함), `CF-IPCountry` JP → JP, 소문자 kr → KR, XX·T1 → null, 이상한 값 → null
- 게임(READY 흉내): 일본 IP + 영어 브라우저 → 처음 방문에 일본어로 한 번 다시 읽음, 🌐 자동(日本語) 선택됨, 하루 안에는 다시 묻지 않음, 영어를 고르면 고정(상점 언어는 그대로), 🌐 자동 → 다시 일본어
- 한국 IP + 일본어 브라우저 → 한국어, 미국 IP + 한국어 브라우저 → 영어, 나라 모름 + 일본어 브라우저 → 일본어, 나라 모름 + 프랑스어 → 영어, 상점 언어가 일본어여도 한국 IP → 한국어, 고른 언어가 있으면 IP보다 우선하고 나라도 묻지 않음
- 지금(READY 전): 한국어, 고르기 숨김, 나라 묻지 않음. `?lang=en` 미리 보기는 그대로 (🌐 자동 없음)
- 번역 e2e 11개, 계정 저장 e2e 63개 통과

## 서버 문구 번역, 게임 다국어 켜기 (dc#62)

### 사용자 요청
- "PR 만들고 머지해줘. 그리고 6단계로 넘어가자." (6단계: 서버가 보내는 문구, 그다음 게임 다국어 켜기)

### 바꾼 것
- **랭킹 장비 보기**: 서버(`api.php`)가 아이템 화면 정보에 아이템 참조(`ref`)·능력치 키(`k`·`v`)·세트 id를 같이 줌 → 랭킹 페이지가 `items.js`로 아이템을 다시 만들어 그 언어의 이름·능력치 줄·부위·등급·세트 이름·세트 효과로 보여줌. 랭킹 목록의 최강 아이템 이름도
  - 예전 기록은 서버가 보여줄 때 한국어 줄에서 키를 채움 (아이템 이름만 한국어로 남고, 기록을 새로 세우면 바뀜)
  - 아이템 참조로 다시 만들기(`fromRef`)를 게임에서 `items.js`로 옮겨 게임·랭킹이 같이 씀
- **우편함**: 서버가 쓰는 메모 4가지(24시간이 지나 돌아온 아이템·등록을 취소한 아이템·○○에게서 산 아이템·○○에게 판매)와 판매 대금 우편의 아이템 이름을 그 언어로. 운영자 선물 메모는 쓴 그대로
- **게스트 이름** "게스트 #ab12cd" → "Guest #ab12cd" / "ゲスト #ab12cd" (로비 목록·머리 위 이름·거래소·랭킹)
- **게임 다국어 켬** (`READY = true`): 이제 모든 사람이 직접 고른 언어 → 접속한 IP의 나라 → 브라우저 언어로 게임을 봄. 위쪽에 언어 고르기(🌐 자동 · 한국어 · English · 日本語)
  - 나라 확인이 실패하면(서버에 `r=geo`가 아직 없을 때 404 등) 보관하지 않고 다음에 다시 물음 → 서버를 올리기 전에는 브라우저 언어
