## 새벽~오전 — 로비, 거래소, 포탈

밤을 새워 이어서 PR을 여섯 개 머지했어요. 혼자 하던 던전이 **사람들이 모이는 로비**와 **아이템을 사고파는 거래소**가 있는 게임이 됐어요.

### 새벽 4시 · 게임 시작 전 로비 (#16)
- 접속하면 바로 던전이 아니라 **넓은 광장(로비)** 에서 시작해요. 가운데 **던전 입구**로 들어가면 모험이 시작돼요
- 같이 접속한 사람들이 광장에서 **@와 이름**으로 보이고, 움직이면 다른 사람 화면에서도 따라 움직여요
- 이름은 랭킹과 같은 가린 이름이에요 (`ab***@...`, `게스트 #xxxxxx`). 이름이 길어 겹쳐 보이는 건 2D 그래픽을 넣을 때 정리하기로 했어요
- 화면 아래 **"같이 접속한 사람들"** 목록: 로비에 있는지, 몇 층을 탐험 중인지 보여요
- 서버: PHP 랭킹 서버에 접속자 위치를 주고받는 기능을 붙였어요 (로비에서는 1초마다, 던전에서는 10초마다). 이메일·기기 ID 원본은 저장하지 않아요
- (이때 만든 "로비로(L)" 버튼은 아래 포탈로 합쳐졌어요)

### 오전 8시 · 거래소·우편함, 포탈과 입구 두 개 (#17)
게임의 핵심은 **아이템 파밍과 사용자끼리의 거래**라서, 로비에 거래소를 열었어요.
- **거래소($)**: 가방의 아이템을 골드·캐시 가격으로 올리고, 다른 사람이 사요
- **수수료**: 모든 거래에 캐시 1. 사는 사람이 가격에 더해 내요. 게임 운영 수익이에요
- **레전더리·세트**는 캐시 가격이 1 이상이어야 해요
- 캐시는 **별도 아이템 없이** 서버가 Xsolla에서 바로 차감·지급해요 (구매자 토큰으로 차감, 판매 대금은 프로젝트 API 키로 지급)
- **우편함**: 판매 대금, 산 아이템, 내린 아이템, **24시간이 지나 안 팔린 아이템**이 와요. 가방이 가득 차면 정리하고 받아요
- 등록·구매·가격·수수료·시간은 전부 **서버에 저장**돼요. 판매자·구매자는 가린 이름과 내부 키로만 남아요
- **복사 방지**: 서버가 아이템마다 주인을 기록해서, 판 아이템의 복사본은 다시 올릴 수 없고 랭킹에서도 인정하지 않아요
- 한계: 골드는 게임에 저장되는 값이라 서버가 잔액을 확인하지 못해요 (캐시는 Xsolla가 확인)

"재시작"을 **"포탈"** 로 바꿨어요.
- **포탈(P)**: 죽지 않았으면 골드·레벨·장비를 그대로 들고 로비로 돌아와요
- 던전 입구에 **문이 두 개**: 왼쪽은 **1층부터**(같은 캐릭터, 새 지도), 오른쪽은 **포탈을 탄 층**으로 (떠난 그대로)
- 왼쪽 문으로 들어가면 기억된 포탈 층이 사라져서, 들어가기 전에 한 번 물어봐요
- 쓰러지면 **"로비에서 새로 시작"**: 골드와 레벨은 처음으로, 장비는 그대로, 1층이 아니라 로비로 와요
- 로비에서 사람마다 **포탈을 탄 층**이 머리 위에 `◎7층`처럼 보이고, 목록에는 "로비 · 포탈 7층"으로 보여요
- "로비"와 "마을"이 섞여 있던 표현을 코드·서버 주소(`lobby`)와 같은 **"로비"** 로 통일했어요

### 오전 8시 반 · 운영자 선물 (#18)
- 서버 명령(`gift.php`)으로 테스터 우편함에 골드·캐시를 넣을 수 있어요. 이메일 원본은 저장하지 않고 이메일 HMAC으로 사람을 찾아요
- 테스터 계정에 골드 99,999와 캐시 99,999를 지급했어요

### 오전 8시 반 · 받기·구매 오류 수정 (#19)
- 선물을 받을 때 **캐시만 들어오고 골드는 안 들어오는 500 오류**가 났어요
- 원인: 서버가 Xsolla를 기다리는 동안 로비 핑이 DB에 쓰면서 SQLite가 "database is locked"로 거절했어요. 구매에도 같은 문제(캐시만 빠지고 아이템이 안 오는)가 있었어요
- DB를 읽고 바로 닫게 고치고, 캐시를 지급·차감한 순간을 먼저 기록해서 중간에 멈춰도 이어서 마무리되게 했어요 (다시 지급·결제하지 않음)
- 멈춘 우편 복구 명령(`gift.php --resume`)을 만들어 테스터 골드를 복구했어요 ✅

### 오전 9시 · 거래소 옆 우편함 (#20)
- 거래소·우편함 **버튼을 없애고** 로비에서 걸어가서만 열게 했어요
- 우편함은 거래소 바로 옆 **작은 빨간 상자**로 옮겼어요. 우편이 오면 깃발이 서요
- 오른쪽 큰 건물은 다음 업데이트 때 쓸 자리라 지금은 **"준비 중"** 이에요

### 오전 9시 · 상점은 보스 전 층에 (#21)
- 상점을 보스 층(5, 10, 15…층)이 아니라 **바로 전 층(4, 9, 14…층)** 에 열어요. 보스와 싸우기 전에 장비를 갖추라고요
- 상점 아이템 레벨은 그 층이라서 한 층 낮아지고 값도 조금 싸져요 (4층 레어 80골드). 골드 양은 그대로예요
- 예전에 보스 층 상점에서 산 아이템도 서버 검증에서 계속 인정해요

### 오늘의 배운 점
- 테스트 서버는 요청을 하나씩 처리해서 동시에 쓰는 문제를 못 잡았어요. 실제 서버처럼 여러 요청을 동시에 보내는 테스트를 추가했어요
- 돈(캐시)이 오가는 단계는 "지급했다/받았다"를 먼저 기록해 두면, 중간에 실패해도 두 번 지급하지 않고 이어서 마무리할 수 있어요

## 오후~밤 — 서버 저장, 새 주소, 랭커와 함께 다듬기

로비와 거래소를 연 그날 오후부터 밤까지 이어서 PR을 열네 개 머지했어요. 광고로 돈을 벌 준비를 하고, 가방을 서버에 저장하고, 게임을 새 주소로 옮겼어요. **120층을 넘긴 첫 랭커**의 피드백으로 게임을 크게 다듬었고, 밤에는 아이템 규칙을 v4로 바꾸고 **최대 층 150층**과 **랭킹 버전(v3 베타 / v4 베타)** 을 만들었어요. 자기 전에는 **고대 아이템 3%**, 예전 주소 정리, **실제 캐시 결제 확인**까지 마쳤어요.

### 광고 보상과 하루 입장 (#22)
- 하루 100명 기준으로 광고 수익을 계산해 봤어요: 한 달 약 $5~$180 (보통 $27). 캐시 부활 한 번($1)이 광고 백 번 정도와 같아서, **캐시와 광고를 같이** 두기로 했어요
- **부활 가격**을 50캐시($5) → **10캐시($1)** 로 내렸어요 (Xsolla 카탈로그에 바로 반영)
- **하루 입장**: 1층 문으로 새로 시작할 때만 세서 **하루 5회 무료**, 그 뒤엔 광고를 보고 입장
- **광고로 대신하기**: 부활 하루 1회(계정 없이도), 거래 수수료 면제 하루 3회. 캐시로 하는 방법은 그대로
- 횟수는 서버가 세요 (한국 시간 자정에 초기화). 광고는 지금 **테스트 광고**(5초 화면)이고, 구글 광고 승인을 받으면 설정만 바꾸면 돼요
- 구글 광고 신청에 필요한 **개인정보처리방침**(`privacy.html`)을 만들고, 게임·상점·랭킹 화면 아래에 링크를 달았어요

### 가방과 진행 상황을 서버에 저장 (#23)
- 로그인한 사람의 **가방, 장착 장비, 강화석, 도감, 진행 중인 판(층·골드·레벨), 상점 상자 보관함**을 게임 서버에 저장해요. 같은 계정이면 다른 기기·나중에 만들 앱에서도 그대로 이어서 해요
- 아이템·골드 거래·층 이동 같은 **중요한 변경은 2초 안에**, 이동·전투(HP 등)는 **1분에 한 번**, 탭을 닫거나 숨길 때는 바로 올려요. 바뀐 게 없으면 보내지 않아요
  - 처음엔 바뀔 때마다 2초 뒤에 올렸는데, 던전에선 턴마다 HP가 바뀌어서 1시간에 1,400번쯤 보내게 돼요. 아직 사용자·수익이 없으니 서버 부담을 줄이자는 의견에 따라 바꿨고, 요청이 약 95% 줄었어요 (1시간 약 60번)
- 두 기기에서 동시에 하면 **먼저 저장한 쪽이 기준**이에요. 늦게 올린 기기는 서버 내용으로 바뀌어서, 서로의 저장을 지우거나 아이템이 복사되지 않아요
- 서버가 잠깐 안 되면 게임은 계속되고 나중에 다시 올려요
- 게스트는 그 기기에만 저장돼요. 화면 위에 "계정을 연결하면 가방과 진행 상황이 서버에 보존돼요" 안내를 띄워요
- 실제 서버에서 저장 번호(rev)가 1 → 3으로 오르는 걸 같이 확인했어요 ✅

### 게임 전용 저장소와 새 주소 (#24, dc 저장소 생성)
- 게임을 GitHub 프로필 저장소(`hucksoon/hucksoon`)에서 **전용 저장소 `hucksoon/dungeon-crawler`** 로 옮겼어요. 지금까지의 기록(커밋)도 그대로 가져갔어요
- 주소는 갖고 있던 도메인의 **`game.apacimtest.com`**. 나중에 웹과 앱을 같이 낼 때 쓰기 좋게 게임만의 주소를 만들었어요 (DNS, GitHub Pages, Xsolla 로그인 허용 주소·CORS, 서버 `allowed_origins`)
  - 새 주소에서 로그인이 "Failed to fetch"로 막혔는데, Xsolla Login의 **Allowed origins(CORS)** 에 새 주소를 넣어서 풀었어요
- 브라우저 저장소는 주소마다 따로라서, 예전 주소는 안내 페이지가 됐어요. 게스트로 하던 가방·진행 상황은 새 주소로 함께 넘겨 주고, 계정은 다시 로그인하면 서버 저장본이 그대로 와요. 예전 상점·랭킹 링크도 새 주소의 같은 페이지로 보내요

### 예전 주소에 남은 계정 장비 옮기기 (#25, dc#1)
- 랭커 한 분의 장비가 새 주소에서 보이지 않았어요. 서버 저장이 생기기 전에 모은 장비가 예전 주소의 브라우저에만 있었는데, 그 뒤 예전 주소를 열지 않고 새 주소로 왔기 때문이에요
- 예전 주소 안내 페이지가 **계정으로 하던 가방·도감·상자 보관함**도 함께 넘기고 (로그인 정보는 빼고), 새 주소에서 그 계정으로 로그인하면 서버 저장본 위에 합쳐서 올려요
- 같은 아이템은 한 번만 들어가고, 가방이 차면 상자 보관함에서 기다려요

### 구글 광고 신청 준비 (dc#1, dc#2)
- AdSense는 최상위 도메인(apacimtest.com)으로 심사해서, apacimtest.com 첫 화면에 **게임 소개 페이지**를 만들었어요 (`site/`): 게임 소개, 특징, 플레이 방법, 장비 등급, 무료로 즐기는 방법, 실제 게임 스크린샷, 개인정보처리방침
- AdSense에 가입해서 게시자 ID를 받고, `ads.txt`와 사이트 확인 코드를 넣어 서버에 올린 뒤 **검토를 요청**했어요 (심사 중)

### 120층 랭커의 피드백 (dc#3)
- **강화석**: 판매하면 아이템 레벨이 높을수록 더 받아요 (레벨당 +5%). 120레벨 레전더리는 16개 → 111개
- **세트는 5개로**: 시험의 세트 효과가 2·4·5개에서 켜져요. 6부위 중 아무거나 5개면 다 켜져서 무기는 자유롭게
- **전부 판매**: 레전더리·세트가 섞여 있으면 "같이 팔까요?"를 물어보고, 남길 수 있어요
- **버튼 위치**: 장착·강화·판매 버튼이 아이템 이름 바로 아래로 올라왔어요
- **버그**: 깊은 보스 층에서 몬스터가 너무 많아 계단 방에 보스 자리가 없으면 층을 만들다 멈추던 문제를 고쳤어요 (보스가 먼저 자리를 잡음)

### 몬스터 20종, 황금 고블린 정예·왕 (dc#3)
- **깊은 층 몬스터 20종**을 더 만들었어요 (모두 40종). 구울·바실리스크(18~20층)부터 그림자 드래곤·대악마·타이탄·공허의 군주·고룡(70~105층부터)까지. 예전에 끝없이 나오던 리치~히드라는 30~50층까지만 나와요
  - 강해지는 건 대부분 층 보정이 맡고, 새 몬스터 기본 능력치는 천천히 올라요. 120층 기준 공격은 1.4배쯤 (깊은 층 사람이 갑자기 막히지 않게)
- **황금 고블린 정예(10층부터 30%)·왕(30층부터 12%)**: 더 단단하고, 더 빨리 도망치고, 맞으면 연막을 터뜨려 순간이동해요. 대신 장비 3·4개, 골드 2·4배. 보통 고블린도 도망까지 24턴으로 줄었어요

- 층 랭킹 **1~3위**는 로비 이름 왼쪽에 **금·은·동 왕관**(가운데 1·2·3). 새 캐릭터로 시작해도 그대로, 밀려나면 1초 안에 사라져요
- 운영자 계정 2개는 이메일 대신 **"운영자"** 로 보이고, 이름 앞에 하늘색 **GM** 방패가 붙어요

### 보조 손, 패링, 광란·견고 세트 (dc#5)
- **고대**는 이제 **레전더리·세트만** 될 수 있어요 (낮은 등급에 너무 자주 붙었어요)
- 7번째 부위 **보조 손**: 절반은 **방패**, 절반은 **보조무기**
  - 보조무기를 끼면 **한 턴에 2번 공격** (왼손은 60%)
  - 방패는 확률로 **패링**(피해 0): 커먼~레어 9~11%, 에픽 16~18%, 레전더리·세트 23~25% 중 하나. 강화로 오르지 않아요
- **광란의 세트**(오른손무기 + 왼손무기): 때린 적 **주변 1칸의 적도 같은 피해**
- **견고의 세트**(도끼 + 방패): **패링 +15%** (최대 40%)
- 아이템 생성 규칙을 **v3**로 올렸어요. 게임과 서버가 v1~v3을 똑같이 다시 만들어 검증하고(2만 개 일치), 예전 v2 아이템도 거래소·우편함·랭킹에서 그대로 써요
  - 테스트하다가 새 아이템이 거래소에 못 올라가는 문제(버전이 v2로 고정돼 있었음)를 찾아 같이 고쳤어요

### 135층에서 캐릭터가 안 보이던 문제 (dc#5)
- 랭커가 포탈로 135층에 다시 들어가자 캐릭터(@)가 안 보이고 능력치가 "--"로 멈췄어요
- 원인: 보스 자리 버그(이미 고침) 때 저장된 층에 **좌표 없는 보스**가 남아 있었고, 그 층을 그리다 오류가 났어요
- 저장된 층을 불러올 때 플레이어 → 적 → 아이템 순서로 빈 바닥에 다시 놓도록 고쳤어요 (보스는 살려서 옮김). 새로고침만 하면 그 자리에서 이어서 해요 ✅

### 아이템 규칙 v4: 부위별 옵션, % 능력치는 등급별 고정 (dc#7)
- 치명타를 따져 보니 예전 규칙은 % 능력치도 아이템 레벨에 비례해서, 깊은 층 레전더리 하나에 치명타가 40% 넘게 붙고 두 개면 상한 75%를 넘었어요
- **부위마다 붙는 주 능력치가 달라요**: 무기는 공격력 + 치명타 피해·공격력%·흡혈, 가슴·팔만 치명타 확률, 투구는 경험치, 장화는 골드, 바지는 방어력%
- 치명타·치명타 피해·공격력%·흡혈·골드·경험치는 **레벨과 상관없이 등급별 고정 범위** (예: 레전더리 주 능력치 치명타 8~10%). 7부위를 모두 레전더리 최대치로 맞춰도 치명타 62%라 상한 밑이에요
- 추가 능력치에 **치명타 피해·공격력%** 추가 (7가지 → 9가지)
- **예전 아이템은 그대로** 두고, 효과를 계산할 때만 % 능력치를 같은 등급 v4 최대치(+강화분)까지 적용해요. 인벤토리·랭킹에 "(적용 10%)"처럼 보여요
- 게임과 서버가 v1~v4를 똑같이 다시 만들고 예전 아이템 상한도 똑같이 계산하는지 3만 개로 확인했어요

### 왜 좋은 아이템 하나면 끝날까: 시뮬레이션
- 플레이하다 보니 "한 번 좋은 아이템을 얻으면 다시 얻을 필요가 없다"는 느낌이 들었어요. 1층부터 150층까지 실제 드롭 규칙으로 줍고, 팔고, 강화하고, 바꿔 끼는 플레이어를 시뮬레이션했어요
- 원인은 두 가지였어요
  - 공격력·방어력이 레벨에 정비례라 깊은 층에서는 20층 더 내려가도 +15% 정도인데, +10 강화는 +100%예요. 그래서 60층에서 얻은 레전더리 +10을 새 에픽이 따라잡으려면 139층을 더 내려가야 했어요
  - 60층부터는 모든 일반 몬스터를 한 방에 잡아요. 더 좋은 장비가 필요 없어요
- 몇 가지 안을 돌려 봤어요
  - 낮은 레벨 아이템에 % 상한·최대 강화 상한만 두면: 오래 쓰는 아이템이 조금 줄지만(최장 120층 → 87층) 초반이 확 어려워져요
  - **깊은 층 몬스터 강화 + 10층마다 아이템 수치가 확 오름 + 구간별 상한**을 같이 하면: 어느 층에서 얻었든 약 40층 뒤엔 새 아이템이 이기고, 깊은 층에서도 2방 정도에 잡혀요. 다만 20~90층 아이템이 지금보다 약해져서 예전 아이템과 맞추는 숙제가 남아요 (남은 일)
- 반대로 **보스는 (보스 배율 × 층 보정)이라 층 수의 제곱으로 강해져요**. v4 기준으로 그 층 최고급 장비로 이길 수 있는 깊이가 약 240층, 보통 파밍 장비는 약 120층이었어요. 이게 최대 층을 정하는 근거가 됐어요

### 최대 층 150층: 일반 던전 완료 (dc#7)
- 일반 던전을 **150층까지**로 정했어요. 150층 보스를 쓰러뜨리고 계단을 밟으면 **일반 던전 완료** 🎉
- 완료하면 안내 창과 함께 **로비로 돌아오고**, 오른쪽 문(포탈)으로 150층의 **새 구역**(새 지도·몬스터·보스)에 들어가 계속 파밍해요. 다시 클리어해도 로비로 돌아와요
  - 처음엔 계단이 바로 150층 새 구역으로 이어지게 했는데, 완료한 순간을 확실히 느끼도록 로비로 돌아오게 바꿨어요
- 아이템 레벨은 얻은 층이라 150보다 높은 아이템은 없어요
- 랭킹에는 "**150층 완료 ✓**"로 보여요. DB를 바꾸지 않으려고 서버 기록값 151을 "완료"로 써요. 같은 기록이면 먼저 세운 사람이 위
- 최대 층이 생기기 전에 더 내려간 판은 150층에서 이어지고, 예전 화면이 더 깊은 층을 보내도 서버가 완료(151)까지만 받아요
- **예전(v1~v3) 장비를 가진 사용자에게 한 번 안내**: 150층 최대 층, v4 규칙, 예전 장비는 % 능력치가 새 기준까지만 적용, 지금 장비로는 150층이 어려울 수 있어 **다시 파밍 권장**, 지금까지의 랭킹은 v3 베타에 그대로. 인벤토리 능력치 창에도 "예전 규칙 장비 N개 착용 중"이 보여요

### 랭킹 버전: v3 베타 최종 기록 + v4 베타 새 랭킹 (dc#8)
- 서버에 올리고 보니 1위가 172층이었어요. 처음엔 150층 완료(151)로 맞추려 했지만, **지금 랭커의 기록은 낮추지 않기로** 했어요
- **지금까지의 랭킹은 "v3 베타" 최종 기록으로 그대로 보관**하고 **"v4 베타" 랭킹을 새로 시작**했어요
- 랭킹 화면 제목 옆에 버전(v4 베타)을 표시하고, 위에 **v4 베타(진행 중) / v3 베타(최종 기록)** 탭을 뒀어요. 주소 끝에 `#v3`를 붙이면 v3 베타가 바로 열려요
- 서버는 기존 표(players)를 v3 베타로 두고 새 표(players_v4)에 기록해요. 기록 올리기와 로비 왕관은 v4 베타만
- 게임은 v4 베타 최고 층을 새로 세요. 진행 중이던 판은 그대로 이어서 하지만, **v4에서 실제로 내려간 층**부터 기록돼요. v4 베타 아이템 랭킹은 v4 아이템만
- 예전 시즌에 깊이 가서 얻은 아이템(예: 172레벨)도 장비로는 계속 인정돼요 (아이템 레벨 검증·거래소는 모든 시즌의 최고 층 기준)
- 서버에 올린 뒤 확인: v3 베타 26명 그대로(1위 172층, 장비 보기 7개), v4 베타는 0명에서 시작 ✅

### 랭킹에 다녀오면 층이 처음부터 시작되던 문제 (dc#8)
- 게임의 랭킹 버튼이 **새 탭**으로 열려서, 랭킹 화면의 "게임으로 돌아가기"를 누르면 원래 게임 탭이 아니라 게임이 하나 더 열렸어요
- 새 탭은 "던전에 있었다"는 정보(탭마다 따로 저장)가 없어서 로비에서 시작했고, 있던 층이 사라진 것처럼 보였어요
- 상점처럼 **같은 탭**에서 열리게 바꿨어요. 돌아오면 있던 층·자리 그대로, 로비에서 갔으면 로비로 돌아와요 (PC·휴대폰 확인)

### 고대 아이템 3%, 예전 주소 정리 (dc#10)
- 고대는 "모든 능력치가 최대치"일 때만이라 v4에서 레전더리·세트 약 2만 개 중 1개였어요. 150층까지 한 번 내려가며 얻는 레전더리·세트가 40~50개라 사실상 못 보는 아이템이었어요
- **새로 얻는 레전더리·세트의 3%가 고대**(모든 능력치 최대치)가 되게 했어요. 한 판(1~150층)에 1개 남짓
- 이미 가진 v4 아이템은 그대로 두고, 버전 표기도 v4 그대로예요. 아이템에 작은 **규칙 개정 번호(r1)** 를 붙여서 새 규칙 아이템만 구분해요 (서버도 똑같이 계산, 6만 개 일치)
  - 버전을 v5로 올리면 랭킹 시즌(v4 베타)과 이름이 헷갈려서, 버전은 두고 개정 번호만 붙이는 방법을 골랐어요
- 서버에도 올려서 새 규칙 파일이 들어간 것까지 확인했어요 ✅
- 예전 주소(`hucksoon.github.io`)는 안내 페이지만 남아 서버를 부르지 않아서, 서버 허용 주소(`config.php`의 `allowed_origins`)와 Xsolla 로그인 허용 주소·콜백 주소에서 뺐어요. 저장소의 기본 설정값에서도 지웠어요
  - 서버 `config.php`에 `allowed_origins`가 두 번 들어 있었는데(PHP는 뒤의 값이 적용), 실제로는 이미 새 주소만 허용되고 있었어요. 헷갈리지 않게 앞의 줄을 지웠어요
  - 지우기 전에 만든 백업(`config.php.bak`)을 웹 폴더에 두면 비밀값이 그대로 보일 수 있어서 바로 지웠어요 (주소로 열면 404 확인). 백업은 웹 폴더 밖에 두기

### 오늘 저녁의 배운 점
- **실제 사용자가 최고의 테스터**예요. 120층까지 가 본 사람의 말로 강화석·세트·판매 화면·몬스터 종류의 빈틈이 한꺼번에 보였어요
- 규칙을 바꿀 때는 **예전에 저장된 데이터**가 가장 위험해요 (예전 주소의 장비, 좌표 없는 보스, v2 아이템). 새 코드만 시험하지 말고 옛 저장본을 불러오는 테스트를 같이 만들었어요
- 서버 비용은 "얼마나 자주 보내는지"가 결정해요. 중요한 순간만 빨리, 나머지는 모아서 보내는 것만으로 요청이 95% 줄었어요
- **느낌을 숫자로** 바꿔 보면 답이 보여요. "다시 얻을 필요가 없다"는 느낌을 시뮬레이션해 보니 원인(강화 +100% vs 레벨 정비례, 한 방에 잡힘)과 진짜 벽(보스의 제곱 성장)이 나왔고, 그걸로 최대 층을 정했어요
- 규칙이 크게 바뀌면 **기존 기록은 낮추지 말고 보관**하는 게 좋아요. 버전(시즌)을 나누면 예전 랭커의 기록도 지키고 새 규칙에서도 공평하게 다시 겨룰 수 있어요
- 테스트가 화면 하나하나는 잘 봐도 **사람의 동선**(랭킹에 갔다가 돌아오기)은 놓쳤어요. 실제로 누르는 순서대로 따라가는 테스트를 더했어요
- **백업은 웹 폴더 밖에**. 비밀값이 든 설정 파일을 웹에서 보이는 폴더에 복사해 두면 주소 하나로 그대로 새어 나갈 수 있어요. 안내할 때부터 안전한 위치를 쓰기로 했어요
