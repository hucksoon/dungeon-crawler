### 할로윈 모습 (게임)
- 테마는 이 기기의 시계(한국 시간 날짜)로 정함. `?event=halloween`으로 미리 보기, `?event=off`로 끄기
- 마을: 보랏빛 → 지평선 주황 하늘, 크고 둥근 주황 보름달, 날아다니는 박쥐 7마리, 처마 밑 거미줄, 가로등은 주황 불빛, 가로등 옆·길가에 잭오랜턴(문은 피함), 창문도 주황
- 몬스터: 머리 꼭대기에 마녀 모자(띠 색 3가지 돌아가며). 그림 모음에 `hw_<몬스터>` 46개를 만들어 두고 `Sprites`가 할로윈일 때 `mon_X` → `hw_X`로 바꿔 그림 (2D·3D 모두). 이미 갓·면류관·왕관을 쓴 저승사자·염라대왕·고블린 왕은 그대로
- 그림(`tools/sprites-build.mjs`): 호박 머리·잭오랜턴·마녀 모자는 직접 그리고, 사신의 낫은 Crawl 그림 모음(CC0)의 `scythe_slant`. 마녀 모자는 몬스터 그림의 머리 꼭대기(불투명한 칸이 있는 맨 위 줄들의 가운데)를 찾아 얹음
- 마을 오른쪽 위 배너(무료 선물 배너가 있으면 그 아래): "🎃 할로윈 이벤트 · 오늘의 호박 사탕 받기"(받을 수 있을 때) / "· 호박 사탕 N개". 누르면 상점의 이벤트 칸으로. 포털 빌드에는 없음(서버·상점이 없음)

### 호박 사탕 (서버 `event.php`, 로그인 계정만)
- `event_status`: 지금 이벤트, 오늘 받았는지, 가진 재화·스킨 (게스트는 이벤트 정보만)
- `event_claim`: 하루 1개(빼빼로데이 2개). 받은 날을 기본 키로 기록해서 같은 날 두 번 못 받음 (동시에 눌러도 하나만)
- `event_skin`: 10개 → 스킨 (계정에 영구, 한 번만)
- `event_cash`: 남은 재화 → 캐시 1:1. 캐시는 우편함으로 보내고, 우편함에서 받으면 Xsolla 계정에 들어감 (기존 우편 캐시 지급 그대로)
- 재화를 쓸 때는 "남은 것 ≥ 쓸 것"일 때만 한 번에 빼서 동시에 두 번 바꿔도 모자라게 쓰지 않음
- 표: `event_wallet`(이벤트마다 남은 것·받은 것), `event_claims`, `event_spends`, `event_skins`. 사용자는 HMAC 키로만
- 시험: 설정 `event_today`로 날짜를 정함. 운영자 기기는 하루 여러 번 받기·시작 7일 전부터 미리 열기

### 상점 (`shop.html`)
- 맨 위에 "🎃 할로윈 이벤트" 칸 (기간 안내 + 카드 4장): 오늘의 무료 호박 사탕 · 호박 머리 · 사신의 낫 · 캐시로 바꾸기(개수 입력, 묻고 나서)

- "액솔라 아이템 기능 중에 매일 1개만 구매 가능하고 매일 한국 시간 오전 10:00 초기화할 수 있는 기능이 있어. 그것을 사용해서 이벤트 재화 중복 구매를 막아줘."

### 기간이 끝나면 원래 모습
- 이미 날짜(한국 시간)로 테마를 정해서 11/14 0시부터 마을·몬스터는 저절로 원래 모습. 얻은 스킨(호박 머리·사신의 낫)은 계정에 남아서 계속 쓸 수 있음

### Xsolla 구매 제한 (하루 1개, 매일 오전 10시 초기화)
- Xsolla 카탈로그에 무료 가상 아이템 `event_coin` ("이벤트 재화 (하루 1개)", 소모형, `game_items` 그룹이라 상점 목록에는 안 보임)을 `tools/xsolla-catalog.mjs --apply`로 만듦
  - `is_free: true`, `limits.per_user.total: 1`, `limits.recurrent_schedule.per_user: { interval_type: daily, time: "10:00:00+09:00" }`, `limit_exceeded_visibility: show`
  - 만든 뒤 Admin API로 확인: 소모형, 다음 초기화 2026-10-31 10:00 (KST)
- 상점 "무료로 받기": Xsolla `POST /free/item/event_coin`(무료 주문, 결제 창 없이 바로 인벤토리) → 게임 서버 `event_claim`
- `event_claim`은 이제 사용자의 Xsolla 인벤토리에서 `event_coin`을 꺼내(소모, 장비 상자·고대 유니크 상자와 같은 방식) 하나마다 그날 개수(빼빼로데이 2개)를 더함. 없으면 아무것도 안 함. 기간 밖이면 꺼내지 않음(아이템은 인벤토리에 그대로)
- 오늘 받았는지: 서버 기록 또는 Xsolla 아이템의 `can_be_bought`. 받았으면 "오늘은 받았어요 · 오전 10시에 또 받기"
- 무료 주문은 됐는데 서버가 꺼내기 전에 창을 닫았으면, 다음에 상점을 열 때 꺼냄
- 받기의 "하루"(`event_xday`, JS `RLEvents.xday`)는 한국 시간 오전 10시에 바뀜 → 받기 기간은 10/31 10:00 ~ 11/14 09:59 (14번), 빼빼로데이 보너스도 11/11 10:00 ~ 11/12 09:59
- 웹훅(`webhook.php`)은 이 무료 주문도 기록만 하고 지급하지 않음 (지급은 `event_claim` 한 곳) → 두 번 들어가지 않음

### 스킨 가격 10 → 6
- `EVENT_SKIN_PRICE`·`RLEvents.SKIN_PRICE` 6. 14일 동안 매일 받으면 15개 → 스킨 2개(12) + 3개는 캐시

### 교환 기간이 끝나면 남은 재화 → 자동으로 캐시 우편
- `event_settle`: 교환 마지막 날(끝나고 7일, 할로윈은 11/20) 다음 날부터, 남은 재화를 0으로 만들면서 같은 개수의 캐시를 우편함에 ("할로윈 이벤트가 끝나서 남은 호박 사탕 N개를 캐시로 바꿨어요"). "남은 개수가 그대로일 때만" 바꿔서 한 번만
- 그 사람이 다음에 접속할 때 실행: 이벤트 상태, 로비(우편 개수에 바로 반영), 우편함. 모두 한꺼번에는 `admin.php event-settle` (몇 번 해도 같음)

### 테스트
- `event-api-test`(37개): 가짜 Xsolla 인벤토리에서 꺼내기, 기간 밖에는 꺼내지 않음, 같은 아이템으로 두 번 못 받음, 오전 10시 하루, 가격 6(스킨 2개 다), 11/20까지는 그대로 · 11/21 접속(이벤트 상태·로비)과 `admin.php event-settle`로 자동 캐시 우편 한 번만

- 설명서 `docs/webshop/brief.json` (AI Kit `shop-builder-assembly`용, 검사 도구 통과)과 순서 안내 `docs/webshop/README.md`
- 판매 칸: 한정 판매(`limited_offers`, 고대 유니크 선택 상자) → 캐시 충전(`cash_packs`) → 장비 상자(`equipment_boxes`, 캐시로). `game_items`(부활권·이벤트 재화)는 뺌
- 같은 Xsolla 프로젝트·같은 로그인이라 게임과 같은 계정 → 캐시 잔액이 이어지고, 산 것은 게임으로

  - 장비 상자: 결제 웹훅 `order_paid` → 서버 `box_grant`가 게임 우편함에
  - 고대 유니크 선택 상자: 서버 `ubox_collect`가 인벤토리에서 꺼내 우편함에 → 우편함에서 고름
- 노트북 작업(PR #129): 상품 그림 9장(`img/shop-items/`, 웹샵 시안의 🎁·◆·▣를 도트 그림으로), `tools/xsolla-catalog.mjs`에 `image_url`, 장비 상자 바로 아래 확률 안내 칸(`description` 블록, 확률표 `shop.html#odds` 링크)

## 블로그 글 양옆 세로 광고 (dc#135)

### 사용자 요청
- "adsence에서 블로그 글 그룹에 광고를 세로형식으로 변경했어. 그래서 내 블로그 글 양 옆에 광고가 보여졌으면 하는데. 코드한번 확인해줄래?"

### 바꾼 것 (`tools/blog-build.mjs`)
- 공개 글 페이지에만 글 양쪽 칸(`aside.rail`)을 두고, 같은 광고 단위 "블로그 글"(`data-ad-slot` 6983849276)을 160×600 고정 크기로 하나씩
- 넓은 화면(1140px 이상, PC)에서만: 가운데 글 760px + 양쪽 칸. 광고는 칸 안에서 `position: sticky`로 위아래로만 따라오고 글을 가리지 않음
  - AdSense 정책: 세로 고정 광고는 PC에서만, 세로로만 움직이고 본문을 가리면 안 됨 (https://support.google.com/adsense/answer/10734935)
- 좁은 화면(태블릿·휴대폰)은 칸을 숨기고 광고도 요청하지 않음 (`matchMedia`로 확인한 뒤에만 `<ins>`를 넣고 push. 숨긴 칸에 요청하면 오류)
- 글 중간 광고 칸(dc#129)은 그대로 (휴대폰에서는 이 칸만)
- 글 목록·게임 이미지·네이버 옮기기 페이지에는 넣지 않음

### 테스트
- `blog-e2e`: 양쪽 칸은 공개 글에만, 1440px에서 160×600 광고 2개가 글 바깥에, 1000px·390px에서는 광고 요청 없음·가로 스크롤 없음 (36개 통과)
- 블로그 그림: `tools/blog-shots.mjs` 장면 `blog-rails` (광고는 막고 자리만 표시)
